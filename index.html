为什么需要设备空间

你的设备越来越多，
你的 AI 却还住在“一台机器”里

手机随身带着，桌面性能更强，云服务器可以 7×24 小时在线——但今天的 AI Agent，往往只能二选一。两种路都走不通。

☁️

云端 Agent

方便，但那是别人的电脑

  • 对话、文件和任务记录，住在服务商的服务器上
  • 长期任务依赖云端一直在线，断网就停摆
  • 你的手机和电脑，降级成了两块“显示器”
📵

单设备 Agent

自主，但走不出这台机器

  • 手机随身，却跑不动重任务、放不下大文件
  • 桌面够强，但你不可能随时坐在它面前
  • 换一台设备，就等于从头开始——上下文丢了，任务断了
🌌

Operit2 的第三条路

你的设备，组成你的空间

  • 不把数据交给云端，也不把 AI 锁在一台机器里
  • 手机、桌面、云服务器组成只属于你个人的设备空间
  • 每台设备保留自己的能力与权限，Agent 在它们之间延续工作

不是“云 vs 本地”的二选一，而是“我的设备听我的”。

架构

三个概念，讲清 Operit2 是怎么工作的

先看通俗版，再看技术定义——同一件事，两种讲法。

01

CoreNode 节点

每一台跑着 Operit 的设备，都是一个独立节点——手机 App 是一个节点，桌面端是一个节点，命令行是一个节点，云上的服务器也是一个节点。每个节点都用自己本机的能力干活：自己的文件、自己的终端、自己的浏览器。节点之间没有“老大”，谁也不比谁高一级。

技术定义CoreNode 是运行 Operit Core 的一个应用实例，由 OperitApplication、LocalCoreProxy 与 HostManager 组成，通过本机 Host 使用文件、终端、浏览器等平台能力。

02

Space 设备空间

Space 就是你亲手配对的设备组成的“自己人圈子”。圈子里的设备会持续同步同一份业务数据——聊天记录、任务、记忆、配置，每台设备手里都有一份完整副本，任何一台掉线了，数据都还在。它不是一台中心服务器，没有谁在“管”谁。

技术定义Space 是多个已建立信任关系的 CoreNode 组成的协作范围，负责确定成员、承载路由流量与持久化同步；它不表达执行位置，也不替代本地执行环境。

03

Binding 任务交接

Binding 是一张“下一棒交给谁”的小纸条。当 Agent 在一台设备上做完一个工具调用、而下一步还没开始的瞬间，它可以把接力棒递给更合适的设备——比如把重计算交给云服务器，把需要你过目的步骤留在手机上。你的对话不用搬家，换个设备，接着跑。

技术定义Binding 以不透明 key 记录其下一次路由执行应由哪个 CoreNode 完成；切换发生在“工具结果已持久化、下一轮模型请求尚未发起”的边界，改变执行位置但不迁移数据。

Space 让设备成为“自己人”，Binding 让任务找到“对的人”。

安全

四条铁律，写在架构里的安全感

01

对等节点，没有“主人”

云服务器可以因为长期在线、算力更强而承担更多任务——但这只是分工，不是加冕。它永远不会因此变成控制其他设备的中心。节点之间，地位永远对等。

02

身份隔离，数据只听你的

身份是本地顶层隔离单位：每个身份名下的聊天、配置与工作区，只在同一身份下、你亲手配对的设备之间同步。身份本身不进入设备间同步，也不会通过 Link 传播——换一个身份，就像换了一个保险柜。

03

Link 接入，信任亲手建立

设备先两两配对，建立直接信任；配对成功不会自动把对方拉进你的空间——加入还是不加入，每一次都要你亲手确认。没有“默认同意”。

04

四层权限，一层比一层紧

运行环境隔离 → Host 系统授权 → AI 能力模式（只读/工作区读写/完整权限）→ 具体工具批准。有影响的单次调用，再问你一次。

必须说清楚的一句：加入设备空间，不等于交出本机文件、终端或管理员权限；“完整权限”也不等于系统提权——操作系统没给的能力，AI 也变不出来。

现状与参与

现在是什么状态？

诚实版现状

Operit2 目前处于预览阶段。Rust Core、平台 Host、节点连接、持久化同步和插件运行时已经有了工程基础，CLI 里已经可以配对设备、管理设备空间；但底层结构、数据格式、插件契约和跨设备流程仍可能发生破坏性更新。能力调度、插件跨节点接续、完整恢复体验还在打磨中。
